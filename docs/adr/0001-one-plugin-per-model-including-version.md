# 0001 プラグインはモデル単位（バージョン・派生を含む）で分ける

- ステータス: 採用
- 日付: 2026-09-23

## 背景（Context）

スキル集はモデルごとに有効なプロンプトを組み立てさせることが目的である。プラグインの粒度として「モデルファミリー単位（例: `qwen-image`）にまとめ、バージョン差は本文で吸収する」案があった。プラグイン数が増えず、モデル更新のたびに配布単位を増やさなくて済む。

しかし画像生成モデルは、同じファミリーでも生い立ち（ベースモデル・蒸留・派生）によって特性が変わり、有効なプロンプトの質が異なる。例えば Black Forest Labs の FLUX.2 Klein は FLUX.2 の派生だが性質は違う。ユーザーはこの差を意識してモデルを選定しており、スキルもその差に合わせて管理することに意義がある。

## 決定（Decision）

- 1プラグイン = 1モデル。`<plugin-name>` はバージョンや派生名を含めてモデルを一意に特定する slug にする（例: `qwen-image-2-1`、`flux-2-klein`）
- 同じファミリーの別バージョン・別派生は別プラグインとして立てる。共通部分の使い回しは、必要になった時点で検討する

## 影響（Consequences）

- プラグイン数はモデル数に比例して増える。marketplace.json の管理コストは受け入れる
- 新バージョンが出たら既存プラグインを上書きせず、新しいプラグインを起こす。旧モデルのスキルはそのまま残り、旧モデルを使い続けるユーザーに効く
- `<plugin-name>` の綴りは公式表記から機械的に導く（`Qwen-Image-2.1` → `qwen-image-2-1`）。表記ゆれが出たら CONTEXT.md に正を書く
