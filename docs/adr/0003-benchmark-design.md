# 0003 ベンチマークは汎用プロンプトを raw と enhanced の対で流し、5軸を人が判定する

- ステータス: 採用
- 日付: 2026-09-23

## 背景（Context）

利用者がモデルの得意不得意を掴むための定型プロンプトを管理したい。モデルごとに最適なプロンプトの書き方が違うという前提（ADR 0001）と、全モデルに同じ条件を与えて比べたいという要求が同時にある。判定は画像を見る人の主観に頼らざるを得ず、順位付けではなく特性の把握が目的である。

## 決定（Decision）

- **問題用紙はモデル非依存の汎用プロンプト**（英語・1〜3文・品質タグなし）で固定する。切り口は12種、t2i 22件・i2i 6件
- **各モデルは raw と enhanced の対で流す**。raw は汎用プロンプトそのまま、enhanced はそのモデルのスキルで書き直したもの。差が「そのモデルに enhance や品質タグが要るか」を示す。スキルがないモデル（基準モデル）は raw のみ
- **判定は人が5軸を 0 / 1 / 2 でつける**。t2i は 忠実 / 補完 / 最良 / 多様 / 品質、i2i は 実行 / 保持 / 転写 / 整合 / 品質。生成は既定 1 枚（seed 1）とし、多様性の軸を見るときだけ seed 1〜4 か問題用紙の `samples`（多様性を見る切り口は 8）で回す
- **品質軸の基準モデルは GPT-Image 2.5**。基準は時期で動くことを受け入れ、判定シートに基準名を残す
- **i2i はネイティブ i2i 対応モデルにだけ流す**。対応の有無はモデルの基本データ（`results/<model-slug>/README.md`）に出典付きで書き、そこで確認できたモデルに限る
- **判定と考察はリポジトリ、生成画像はローカル**（`_local/`、git 管理外）。i2i の参照画像だけは再現性のため `refs/` にリポジトリで固定する。参照画像は自前生成の架空の人物・物品に限る
- 人物は架空の成人のみ。実在の人物名・キャラクター名は使わない

## 影響（Consequences）

- 1モデルあたりの生成枚数は t2i で raw / enhanced 各 25 枚（画風の変種を含む）。seed 4 種で回すと各 100 枚
- 汎用プロンプトを変えると既存の判定と比較できなくなる。`id` は変えず、変えた問題用紙の判定行を消す
- 道具立ては判定シート（Markdown）のみ。コンタクトシート生成や集計のスクリプトは、判定が回り始めて必要になったら足す
