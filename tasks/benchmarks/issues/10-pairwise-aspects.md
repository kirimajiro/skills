# 10 一対比較の観点セットを定め、問題用紙に `pairwise:` を追記する

Type: grilling
Story: pairwise
Status: resolved

## 背景

5 軸のルーブリックで 3 枚を見比べながら観点ごとに 3 段階を付けるのは判定者の負担が大きかった（チケット 03・07・08）。今後の判定は「同じ問題用紙の 2 枚を並べ、1 観点ずつ 2 択で答える」一対比較に切り替える。勝敗を競うのではなく、多数の 2 択から「このモデルは何に強いか」「ローカル A vs B で観点ごとにどちらが優れるか」を浮かび上がらせ、見終わった後の感想戦（雑感のヒアリング）を主体にする。

## 目的

設問（観点）の体系を固定する。観点はこれまでの備考・雑感で判定者が実際に使った語彙から起こし、リポジトリ全体で共通の ID を持つ。問題用紙ごとに該当する観点を選び、その問題用紙向けの一言の設問を書く。問題用紙の「見るもの」は変えない。

## 観点セットの草案（grill で確定する）

判定者の備考（`results/*/t2i.md`）に現れた語彙から起こした案。10 前後に収める。

| ID | 観点 | 設問の型 | 由来（備考の語彙） |
|---|---|---|---|
| texture | 質感の本物感 | どちらが 3D・CG っぽくなく、本物の写真（絵）に見えるか | 3D 感・粘土感・プラスチック感（01・02・03・05・09・15・20） |
| detail | ディテールとグランジ | 汚れ・傷・経年・書き込みの説得力はどちらか | グランジがない・ディテール不足（03・05・11） |
| text | 文字の正確さ | 指示した文字列・字形はどちらが正確か | 漢字が崩れる・文字は全部おかしい（05・06・17・18・21・23） |
| layout | 文字とレイアウト | 文字の配置・全体の設計はどちらが良いか | レイアウトがダサい・単調（06・21・22） |
| structure | 構造物とパース | 直線・遠近・構造の整合はどちらか | パース・トラスと影・橋の構造・エンジンの機構（10・11・16・18・23） |
| anatomy | 人体・手指・ポーズ | 関節・手指・ポーズの自然さはどちらか | 手が 3 本・取っ手のない側を握る・振り返っていない（04・07・08・14・23） |

| context | 補完の文脈適合 | 指示にない要素はどちらが場面に合っているか | 屋台感が少ない・ラーメン店としての書き込み（01・02・03・06・17） |

| light | 光と素材 | 逆光・艶・透過などの光の扱いはどちらか | シズル感・麺が浮く（19・20） |

## 手順

1. /grill-me で草案を詰める: 観点の数（10 前後）、ID と日本語名、設問の型の言い回し、「補完」と「文脈」の切り分け、culture（文化的な正しさ）を独立させるか structure / context に吸収するか
2. `benchmarks/README.md` に「観点セット」の節を置き、5 軸ルーブリックの節と置き換える（旧ルーブリックは git が担う）
3. 各 `benchmarks/t2i/NN-*.md` の frontmatter に `pairwise:` を追記する。1 問題用紙あたり 2〜4 観点。書式:

   ```yaml
   pairwise:
     - aspect: text
       q: 看板の "Blue Heron Coffee" と黒板の "Open 7am – 4pm" はどちらが正確か
     - aspect: texture
       q: 店先の木・壁・真鍮はどちらが本物に見えるか
   ```

4. `CONTEXT.md` に用語を追加する: 観点（aspect）・一対比較・セッション・感想戦

## 受け入れ条件

- Given 観点セット、When `benchmarks/README.md` を読む、Then ID・日本語名・設問の型が表で並び、5 軸ルーブリックの節がない
- Given 23 件の問題用紙、When frontmatter を見る、Then すべてに `pairwise:` があり、各 aspect が観点セットの ID に存在する
- Given 観点セット、When 判定者の備考の語彙（3D 感・文字・パース・手指・肌・レイアウト）を当てる、Then いずれかの観点に収まる

## Comments

## Answer

- 観点は草案 12 に `culture`（独立）と `fidelity`（omnibus 用。多要素の指示がどちらに多く揃うか）を加えた 14。一覧は `benchmarks/README.md` の「観点セット」
- 「指示の忠実さ」は一般には観点にしない（多くのモデルが指示どおりに描けるため）。崩れやすい omnibus（t2i-23）だけ、要素群ごとに `fidelity` の設問を複数置く
- 設問文の言い回しは問題用紙ごとに自由。1 問題用紙 3〜4 観点、t2i-23 は 7
- 問題用紙の frontmatter に `pairwise:` に加えて `summary:`（日本語 1 行要約）を追記した。作業用紙（eval-sheet）はチケット 13 で外れるので、一対比較の画面に出す要約の恒久的な置き場が要るため
- 用語（観点・一対比較・セッション・感想戦）を `CONTEXT.md` に追加し、5軸の定義を i2i 限定に改めた
