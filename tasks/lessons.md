# Lessons Learned

- _ops [meta] 教訓の記録・統合・失効はこのファイル末尾の運用ルールに従う
- p7kd [process] プラグインの粒度・分割などモデル選定に関わる方針は、他プロジェクトの慣習から推定せずユーザーに確認してから AGENTS.md に書く
- w3qn [process] 人が判定する作業は 1 問ずつのウィザードにせず、モデル単位の作業用紙（`_local/<model-slug>/<mode>/eval-sheet.md`）に一括記入してもらい、Claude が判定シートへ転記する
- k4vx [process] ファイル全体を書き直す前に元ファイルを `.trash/` にコピーし、書き直し後に落ちた節がないか件数で照合する（リポジトリは git 管理外）

## 詳細

### p7kd 粒度の方針は推定で書かない
- trigger: AGENTS.md・CONTEXT.md にプラグインやスキルの分割単位・命名の方針を書くとき
- 事例: 「バージョン差はプラグインを増やさない」を推奨として AGENTS.md に書き、最初のスキル配置時に「モデルの生い立ちで特性が変わるので別プラグインにしたい」と差し戻された（2026-09-23。ADR 0001）
- 理由: 粒度はユーザーがモデルを選定する軸そのもの。管理コストの都合で決めると、スキル集の存在意義（モデルごとの差に合わせる）とぶつかる

### w3qn 判定は作業用紙で一括
- trigger: ベンチマークの判定（5 軸の記入）をユーザーに依頼するとき
- 事例: t2i-01 から 1 問ずつ点数を聞くウィザードを始めたところ、「モデル毎に全画像を一括評価するので、1 画像ずつのプロンプトの要約付きの評価用紙 md を作成してください」と差し戻された（2026-09-24。チケット 03）
- 理由: 判定者は画像を続けて見比べながら付けたい。往復回数が減り、要約・見るもの・表が 1 ファイルに揃うほうが判断が安定する。転記は Claude がスクリプトで行える

### k4vx 全面書き直しの前に退避
- trigger: 判定シート・README など既存ファイルをスクリプトや Write で丸ごと置き換えるとき
- 事例: krea の判定シートを一対比較書式に書き直した際、見出しの前に改行がなかった t2i-17 の enhanced プロンプトが抽出から漏れ、git 管理外のため PNG のメタデータから復元した（2026-09-24。チケット 14）
- 理由: このリポジトリは git 未初期化で、上書きは取り消せない。退避と件数照合（問題用紙 23 = 節 23）で数秒で防げる

### _ops 運用ルール
- 記録: セクション1に1行（`- <id> [<tag>] <rule一行>`）を追加し、セクション2に同idの詳細ブロック（`### <id> 見出し` + trigger/事例/理由、任意でexpiry、各1行・最大6行）を追加する。詳細が収まらないときは別ファイルへ切り出しrule行から参照する
- id: 小文字英数字4文字。連番にせず、既存idと衝突しないランダムな組を採番する（`_ops`は予約）
- tag: model（対象モデルの仕様・挙動）/ skill（SKILL.md の構成・description・トリガー）/ research（出典・公式確認）/ distribution（marketplace.json・version）/ process（手順・ツール）/ meta。既存tagで表せない場合のみ追加してよい
- 読み方: 1行目の指示に従う。詳細ブロックは `grep -A6 '^### <id>'` で取得可
- 出口: 同系統3件で1件に統合。常時適用すべきものはAGENTS.md・README.md等へ昇格し削除。expiryが成立したら削除（経緯はgitが担う）。`_ops`を除き30件を超えたら、次に記録するセッションで統合・昇格・失効レビューを必須で行い30件以下へ戻す
